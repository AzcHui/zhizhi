# 给只只写一套台词

只只的「说什么」全是数据，代码只是一层薄薄的搬运（`packages/plugins/persona-zhi/src/index.ts` 只做 `读 JSON → 交给 SDK`）。所以换人格 = 换一份 JSON，**不用改代码、不用重新 build**。

这个技能的唯一产物是**一个 JSON 文件**。它不碰阈值、不碰沉默机制、不碰通道 —— 那些是内核宪法。

## 先决条件（先读，别急着动笔）

1. **读现有台词本**：`packages/plugins/persona-zhi/persona.json`。它既是最好的格式样例，也是「语气标尺」。**不要凭空发明格式。**
2. **确认要写到哪**：
   - 用户自己的台词 → `data/user.json`（数据目录，通常就是仓库根的 `data/`）
   - **不要动** `packages/plugins/persona-zhi/persona.json`（内置包，是所有人的默认值，也是「删掉 user.json 就能恢复」的底气）
3. **检查 `data/user.json` 是否已存在**。存在就**先把原文件内容给用户看**（或备份成 `user.json.bak`），经确认再写。**绝不静默覆盖。**

## 五步流程

### 第 1 步 · 问清要什么

一次问完，不要来回挤：

- **人格方向**：毒舌 / 温柔 / 冷淡 / 元气 / 中年程序员 / 猫……（用形容词也行，但要落到「它怎么评价你的电脑和你的作息」）
- **改动范围**：整套换（模式 A）还是只改某几段（模式 B）
- **称呼**：怎么称呼用户（你 / 老板 / 主人 / 不称呼）
- **禁区**：有没有不能碰的话题（催睡觉？说教？脏话？）

### 第 2 步 · 选模式

| 模式 | 什么时候用 | 怎么做 |
|---|---|---|
| **A · 整套换** | 用户要「换一个人格」 | 从 `reference/example-min.json` 起步，按 schema 补全其余段 |
| **B · 只改指定段**（更常用、风险更低） | 「把告警台词改凶一点」「闲聊别那么啰嗦」 | **以现有台词本为基线，只替换指定的段，其余原样保留** |

模式 B 请务必复制基线文件再改，不要手打整份。

### 第 3 步 · 写台词

**规矩全在 `reference/schema.md`（每段什么时候说、要几句）和 `reference/tone.md`（什么样算过头）里。写之前必须读这两份。**

先看 `reference/schema.md` 的「每段什么时候说」再动笔 —— **时段写错比写得好不好严重得多**（在用户打字时说「你半天没动了」，一句就露馅）。

另外记住：`data/user.json` 是**插在最前面的一层**，不是替换。你漏掉的段会由内置台词包接着说 —— **两套语气会混搭**。
- 只改几段（模式 B）→ 混搭没关系
- 换一整个人格（模式 A）→ **必须覆盖全部 12 个段**

### 第 4 步 · 机器校验（不许跳过）

```bash
node skills/zhizhi-persona/scripts/check-persona.mjs <你的文件.json>
```

**必须退出码 0**。有 ERROR 就改到 0；WARN 逐条向用户说明「为什么保留」。

这一步是整条流程里唯一能挡住低级错误的地方 —— 句数不够、占位符丢失、段名拼错、`id` 撞车，都能查出来。

### 第 5 步 · 给用户预览

**不要让用户读 JSON 判断好坏。** 用表格给他看：

```
| 段 | 句数 | 抽样（3 句） |
|---|---|---|
| chitchat | 40 | … |
```

再挑 5~8 句完整的念一遍（就是它以后会说的话）。用户点头再落盘。

## 五条铁律（这五条是踩过坑写下来的）

1. **`chitchat` 至少 30 句，建议 40 句。**
   台词"说过"是**永久记账**的（`memory.ts` 的 `isStale`）—— 说过一次就永远算旧。只给 5~8 句，一天 24 句的节奏下**当天就循环 5 圈**，用户立刻听出来。

2. **占位符必须原样保留。`{value}` 不许改写成「数值」或省略。**
   这是**静默错误**：写错不报错，用户看到的就是字面量 `{value}%`。允许的占位符只有：`{value}` `{count}` `{name}` `{command}` `{drive}` `{publisher}` `{summary}`。

3. **每段要说的话，必须和它被触发的时机对得上。**
   最容易错的是 `chitchat`：它是**用户在电脑前时**说的闲话。写成「你半天没动了」会当场露馅 —— 那是 `chitchat_back`（用户离开又回来）的语义。

4. **`id` 不能叫 `persona-zhi`。**
   与内置包重名 → 内核 WRN 后**直接跳过**，整套台词一个字都不生效，而且只留一条警告。

5. **不许说教、不许催、不许骂人。**
   只只的定位是「有人味 · 会吐槽你 · 但不说教、不催你」。吐槽是**吐槽电脑和处境**，不是吐槽用户。判据见 `reference/tone.md`。

## 输出与安全

- 写 `data/user.json`，**不写** `packages/plugins/persona-zhi/persona.json`
- 文件已存在 → 先备份 / 先给用户看，确认后再写
- 写完后告诉用户：**删掉这个文件就恢复默认人格**
- 生效方式：重启只只（台词是启动时读的，没有热重载）
