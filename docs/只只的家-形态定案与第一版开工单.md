## 一、定案

### 1.1 一句话

**「只只的家」= WPF 内嵌 WebView2 ＋ Vue3 单页的独立窗口**，承载低频、结构化、可编辑的内容；
浮窗（330×250 那颗球 + 小面板）保持原样，只做高频「随手看一眼」。

### 1.2 为什么不是「本地网页服务」

| 否决理由 | 说明 |
|---|---|
| 要新增传输层 | 内核现在是 `stdin/stdout` 单飞（stdout 只走数据、stderr 只走日志），加 HTTP server 是把简单变复杂 |
| **端口冲突** | 用户明确的长期红线（曾被后端端口占用坑过），常驻 server 必占端口 |
| 安全面变大 | 监听端口 = 本机/局域网其它程序可访问，得额外做 token |
| 方向错误 | 「远程访问」是「做平台」的路，本项目已明确放弃做平台 |

### 1.3 为什么不是纯 WPF

这六块界面本质是**表格 + 列表 + 日志流 + 表单**，是 Web 技术舒适区、WPF 最难受的地方。
更关键：**C# 不是用户的主场（Vue3 + Element Plus 才是）**，而这块界面会反复改十几次。

### 1.4 WebView2 的代价（认下来才用）

| 代价 | 数值 | 应对 |
|---|---|---|
| 内存 | 单个实例约 80~150 MB | **只在打开家时创建，关窗即 Dispose** —— 常驻仍只有球 + Node 内核 |
| 首次创建耗时 | 300~800 ms | 接受（开家是低频动作） |
| 运行时依赖 | 需 Edge WebView2 Runtime | Win11 自带；Win10 需装。启动时检测，缺失给提示 + 官方下载链接 |
| 新一层桥 | 前端 ↔ WPF 的 postMessage 协议 | 协议很小（见 3.3），且**命令复用现有内核事件，不新增 API 层** |

### 1.5 三分区原则（以后别再混）

| 位置 | 频率 | 放什么 | 纪律 |
|---|---|---|---|
| **浮窗小面板** | 高频，随手扫 | CPU/MEM、前台类别、信任档、静音倒计时、三个按钮 | **不再长大**（已 206 DIP 宽、零余量） |
| **家** | 低频，坐下看/改 | 台词池、消息历史、日志、（二版）插件与设置 | 打开才创建，关掉即销毁 |
| **CLI** | 自动化/验收 | `--self-test` / `--render-test` / 探针 | 不动 |

## 三、技术规格

### 3.1 窗口

| 项 | 值 |
|---|---|
| 尺寸 | 900 × 640；`MinWidth 760` / `MinHeight 520` |
| 边框 | `WindowStyle = SingleBorderWindow`，`ResizeMode = CanResize` |
| 任务栏 | **`ShowInTaskbar = true`**（与浮窗相反 —— 它要能 Alt+Tab 切到、能关） |
| 置顶 | **`Topmost = false`**（浮窗是 true，两者别混） |
| 首次位置 | 屏幕居中；之后从 `shell.json` 恢复 |
| 关闭行为 | **`Close()` → Dispose WebView2 并释放窗口**（下次打开重建）。不做 Hide 常驻 —— 守「轻」 |
| 单例 | 已开着 → `Activate()` + `WindowState = Normal`，不建第二个 |

**已知行为（不修）**：浮窗是 `Topmost`，家在前台时球仍浮在最上层。球只在角落 76px，可拖动避开。若实测碍事再议。

### 3.2 前端

```
apps/home/                    # 新增（pnpm workspace 加 "apps/*"）
  index.html
  vite.config.ts              # base: './' —— 产物走相对路径
  package.json                # name: @zhizhi/home
  src/
    main.ts
    bridge.ts                 # postMessage 收发封装（唯一与外壳耦合的文件）
    views/Overview.vue        # 概览
    views/Lines.vue           # 台词池（含试听按钮）
    views/History.vue         # 消息历史
    views/Logs.vue            # 日志
```

- 技术栈：**Vue3 + TS + Vite**（用户主场，后续自己也能改）；样式轻量，不引入大 UI 库（4 个页面不值得）
- 构建：根 `package.json` 加 `"build:home": "pnpm --filter @zhizhi/home build"`
- **产物 `apps/home/dist/` 不进 git**（`.gitignore` 加一行，跟 `zhi-shell.render*.png` 同处理）

**加载方式（关键）**：不能用 `file://`（ES module + fetch 会被 CORS 卡死）。用官方做法：

```csharp
// 目录映射成虚拟主机
await webView.EnsureCoreWebView2Async(env);
webView.CoreWebView2.SetVirtualHostNameToFolderMapping(
    "zhizhi.home", distPath,
    CoreWebView2HostResourceAccessKind.DenyCors);
webView.CoreWebView2.Navigate("https://zhizhi.home/index.html");
```

**用户数据目录（另一个坑）**：WebView2 默认把缓存写在 exe 同目录（`Zhizhi.Shell.exe.WebView2\`），会污染代码目录。必须指定：

```csharp
var env = await CoreWebView2Environment.CreateAsync(
    browserExecutableFolder: null,
    userDataFolder: Path.Combine(
        Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
        "zhizhi", "webview2"),
    options: null);
```

**dist 未构建时**：不要白屏。检测 `dist/index.html` 不存在 → 窗口里显示一段纯 HTML 提示「前端未构建，请运行 `pnpm build:home`」。

### 3.3 桥协议（前端 ↔ 外壳）

两个方向都用 JSON，**不含业务逻辑，只搬数据**。

**前端 → 外壳**：`window.chrome.webview.postMessage({ cmd, ...args })`

| cmd | 参数 | 外壳响应 |
|---|---|---|
| `ready` | — | 回 `overview` + `pools` + `history`（首屏） |
| `getOverview` | — | 回 `overview` |
| `getHistory` | `{ limit, offset, type? }` | 回 `history`（**倒序**分页，读 events.jsonl 尾部） |
| `getPools` | — | 回 `pools`（三层合并，每条标 `source: user／persona／learned`） |
| `previewLine` | `{ text }` | **试听**（口径见 3.5），回 `previewDone` |
| `getLogs` | `{ limit }` | 回 `logs`（外壳日志尾部 + 内核 stderr 环形缓冲最近 N 条） |
| `subscribeLogs` | `{ on: boolean }` | 开/关实时推 `logLine` |

**外壳 → 前端**：`webView.CoreWebView2.PostWebMessageAsJson(json)`

| 类型 | 内容 |
|---|---|
| `overview` | `{ cpu, mem, trust, fgClass, idleSec, muteLeftMin, uptimeSec, kernelRunning }` —— 数据全部来自已有的 `Sample`/`FeedIdle` 内存字段，**不重新采集** |
| `history` | `{ total, items: [{ ts, type, severity, text }] }` |
| `pools` | `{ sections: [{ type, lines: [{ text, source }] }] }` |
| `logs` / `logLine` | `{ ts, source: shell／kernel, text }` |
| `previewDone` | `{ ok: boolean }` |

### 3.4 内核改动（只有两处，都很小）

1. **新增一条 stdout 数据行**（启动时一次）：
   ```json
   {"type":"hello","dataDir":"D:\\MyProjects\\zhizhi\\data","version":"0.0.0"}
   ```
   理由：外壳需要真实 `dataDir`（读 events.jsonl / 台词池），**不能自己硬拼**（打包后会变）。
   外壳在 `OnStdout` 里加一个 `type === "hello"` 分支，存下来即可，不影响现有 `event` 解析。

2. **`previewLine` 不走内核** —— 见 3.5，**内核零改动**。

### 3.5 试听口径（重要）

**试听 = 纯预览，不污染记忆。**

- 不进 `events.jsonl`、不动 `trust`、不计 `occurrence`（否则你点 200 次试听，亲密度和去重记账全被搅乱）
- 实现：外壳 `FloatWindow` 新增公开方法
  ```csharp
  /// <summary>家 · 台词试听：让球冒这句话（纯预览，不进记忆、不影响 trust/计数）。</summary>
  public void PreviewLine(string text) => EnqueueBubble(new SaidLine("preview@", "info", text));
  ```
  ⚠️ **不要调 `ExpandPanel()`**（现有 `ShowTestBubble` 会展开面板，试听时展开会挡住你正在看的列表）
- 冒泡仍走现有管道：队列 + 打字机 + TTL，与真实台词观感一致

### 3.7 入口与退出路径（2026-10-22 10:13 用户提出）

**为什么改**：Windows 软件的惯例是「退出」放托盘右键 —— 它是低频且不可逆的动作，不该占主面板的位置；主面板留给常用操作。

| 动作 | 入口 |
|---|---|
| 打开家 | ① 面板第三按钮「**进屋**」 ② 托盘右键「只只的家」 |
| 退出 | **只留托盘右键「退出」** |

**三条纪律**：

1. **按钮名用「进屋」**。理由：2 个字，与「挪一挪」「静一下」同节奏（都是 `动词 + 补语` 的口语），且**避开「回」字** —— 「回家」会和托盘里已有的「回到右下角」撞义。tooltip 写全称「打开只只的家」。
   - 备选：「开开门」（3 字，更有人味，指代略虚）／「打开家」（3 字，最直白但生硬，且按钮行余量从 24 DIP 掉到 11 DIP，布局变紧）
   - ❌ 「只只的家」5 个字放不下 —— 按钮行会顶破 `PanelMaxWidth=206` 的限宽

2. **点「进屋」后立刻 `CollapsePanel()`** —— 否则家窗口已经弹出来，面板还悬在球旁边，看着像两个窗口打架。

3. **托盘初始化失败时必须留后路（防呆，别漏）**：`InitTray()` 是 try/catch，失败只记账不崩。一旦托盘没建起来，用户就**再没有任何退出入口**（只能任务管理器杀进程）。
   → 面板第三按钮做成**动态**：托盘 OK → 「进屋」；托盘失败 → 仍显示「退出」。
   ```csharp
   // MakePanel 里不要写死文案：托盘成败决定这格是"进屋"还是"退出"
   homeOrExitBtn.Content = _trayOk ? "进屋" : "退出";
   ```

**不要做的事**：家打开时**不禁用**这个按钮（内核停了也要能进家看日志 —— 那正是最需要它的时候，家是排查入口）。

## 五、验收（第一版）

### 5.1 自动（新增 `--home-test`）

```
Zhizhi.Shell.exe --home-test
```

流程：建家窗口 → 等 WebView2 初始化 → 等前端 `ready` → 回 `overview` → 前端回显 →
截图 → 关窗 → 退出码 0。

| # | 判据 |
|---|---|
| ① | `CoreWebView2Environment.GetAvailableBrowserVersionString()` 非 null（运行时在位） |
| ② | 收到前端 `ready`（说明 dist 加载成功、`bridge.ts` 通了） |
| ③ | `overview` 回传后前端回显字段数 ≥ 5（说明桥是双向的，不是只发不收） |
| ④ | `getHistory` 返回条数 > 0（`events.jsonl` 存在时）—— 证明真的读到了盘 |
| ⑤ | 截图里能看到四个页签（人眼复核一次） |

### 5.2 手动（用户验）

1. 托盘 → 「只只的家」→ 窗口出现，出现在任务栏
2. 台词池 → 随便点一句的「只说这句」→ **球冒这句话**（面板不展开）
3. 概览的 CPU 数字 ≈ 浮窗面板上的 CPU 数字（同一个采样源）
4. 日志页切到「实时」→ 说一句话 → 日志里有对应行滚动
5. 关掉家 → 任务管理器里 `msedgewebview2.exe` 消失（**内存回来了**）
6. 再开一次 → 位置尺寸与上次一致
7. **面板第三按钮是「进屋」**（不是「退出」）；点它 → 家打开，且**面板自动收起**
8. **托盘右键「退出」仍能正常退出**（这是唯一的退出路径，必须验）
9. 模拟托盘失败（临时让 `InitTray` 抛一次）→ 面板第三按钮**变回「退出」**（防呆后路）
