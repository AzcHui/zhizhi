## 一、通用验收清单（每次照这个核）

### A · 当期验收标准

- [ ] 打开《只只-开发进度报表》→ 取当前里程碑的「✅ 验收标准」
- [ ] **独立跑一遍**（不接受"我测过没问题"），把原始输出贴进记录
- [ ] 确认数据是**真实**的，不是编的（如指标值与本机实际相符）

### B · 四条硬约束（M0 起永久有效）

| # | 约束 | 怎么核 |
|---|---|---|
| 1 | `core` **零 UI 依赖 / 零外部依赖** | 看 `core/package.json` 的 `dependencies`；Grep 源码只应有 `node:*` 与包内相对路径 |
| 2 | **插件间禁止互相 import** | Grep 插件源码：只允许 `@zhizhi/plugin-sdk`，出现任何 `@zhizhi/probe-*` 互引即违规 |
| 3 | **官方插件走同一套 SDK**（dogfooding） | 官方插件必须用 `define-*`，并经 `registry` 同一路径注册，不许有内核特权 |
| 4 | **插件崩溃不带崩内核** | 加载 / 采样 / 事件分发各层都有独立 try/catch 隔离 |

### C · 架构边界（防漂移）

- [ ] **内核 7 样**没被外放：事件总线 · 调度器 · 状态存储 · 分通道规则 · **沉默机制** · 权限裁决 · 插件加载器
- [ ] **跨插件数据结构只在 `core/types.ts` 定义**（插件不许自己另发明一套）
- [ ] **6 类扩展点契约保持一致**：`probe / rule / persona / channel / action / view`
      —— 若某类暂不实现，**必须在《进度报表》标注"有意推迟"**，避免日后误以为写过
- [ ] 没有"**为还不存在的问题提前付成本**"的新代码（动态加载器 / 沙箱 / 插件市场 = 都要等触发条件）

### D · 工程卫生

- [ ] `pnpm typecheck` 零错误
- [ ] 无意外死代码 —— 契约即便暂无消费方也可以存在（契约先行），但要在报表标注「备件 · 待 Mx 接线」
- [ ] `git` 工作区干净；提交信息符合 `<type>(<scope>): <desc>` 风格

### E · 前瞻风险（监工最该说的一节）

- [ ] 当前设计是否给**下一个里程碑**埋坑？明确写出来 + 给备选出路
- [ ] 有无"现在 5 行能改、以后 500 行才能改"的地方？

## 二、验收记录

### M0 · 骨架跑起来 —— ✅ **通过**（2026-10-14）

**A · 验收标准**
> `pnpm --filter cli start` → 终端每 5 秒打印一行指标 JSON

| 检查 | 结果 |
|---|---|
| 3 个插件激活 | ✅ `probe-cpu / probe-mem / probe-disk` 全部 `已激活` |
| 每 5 秒一行 | ✅ tick1 `06:19:18` → tick2 `06:19:23`（5.005s） |
| 单行 JSON | ✅ 一行一 tick，无多行污染 |
| stdout/stderr 分离 | ✅ 数据走 stdout、日志走 stderr |
| 数据真实 | ✅ CPU 12 核（i5-12450H 8核12线程✓）· 内存 31.7GB ✓ · C/D/E 余量与实测一致 |
| `pnpm typecheck` | ✅ 零错误 |
| `pnpm once` | ✅ 3 轮自退 |
| 优雅退出 | ✅ `只只下班了。` |

**B · 四条硬约束**

| # | 约束 | 实测 | 判定 |
|---|---|---|---|
| 1 | core 零依赖 | `dependencies: {}`；源码只 import `node:*` | ✅ |
| 2 | 插件互不 import | Grep 全量：3 个 probe **仅** import `@zhizhi/plugin-sdk` | ✅ |
| 3 | 官方插件同 SDK | 全用 `defineProbe()`，走 `registry.registerProbe()` 同路径 | ✅ |
| 4 | 插件崩不带崩内核 | **4 层隔离**：registry `#load` · bus 逐订阅者 · scheduler tick · cli `sampleAll` | ✅ 超额 |

**C · 架构边界**
- ✅ 内核 7 样均未外放；跨插件类型集中于 `core/types.ts`
- ✅ 插件零外部依赖（只用 `node:os` / `node:fs`）—— 装机体积与攻击面都小，对"安全哨兵"是加分
- ✅ 无"提前付成本"：动态加载 / 沙箱 / 权限执行均未动工（符合 S1 契约先行）
- ⚠️ **6 类扩展点中 `action` / `view` 尚未提供 `define-*`** —— M0 只需要 probe，属合理未做，但**需在报表标注"有意推迟"**

**D · 工程卫生**
- ✅ 类型检查干净；工作区干净；提交 `4cc7918 feat(core): M0 骨架跑起来……` 规范
- ℹ️ 现有「备件」（**非缺陷**，属契约先行）：`manifest.json`×3 与 `validateManifest()` 暂无消费方；`Bus` / `Store` / `Dispatcher` 未接线；`gates` 为 passThrough 占位
      → 运行时日志自证：`bus=0 topic · store=0 项 · gates=4 道 · channels=0 个`

**E · 前瞻风险**

| 级别 | 风险 | 说明 | 建议出路 |
|---|---|---|---|
| ✅ 已覆盖 | ~~M1 验收标准用当前架构过不了~~ | M1 要"删掉 `probe-cpu` 后仍能跑"，但 M0 的 cli 是**静态 import** —— 包不存在时 Node 在**模块解析阶段**就 `ERR_MODULE_NOT_FOUND`，进程直接死，**根本进不到 registry 的 try/catch** | **用户已在《进度报表》第三节的 M1 拆解中提前覆盖**：改成「清单驱动 + 动态 `import()` + 缺失进 `failed` 列表」，并把验收措辞改为「把 `probe-cpu` **从清单里**去掉」。方案正确。⚠️ 实施另有 2 个坑，见下 |
| 🟡 中 | **Scheduler 的 tick 会重叠** | `setInterval` + async handler 不等上一次完成。M0 采样 1.6~2.4ms 无妨；**M2 加进程枚举、M8 加基线快照后**，单次一旦 >5s 就会并发打架 | M2 顺手改「自调度 `setTimeout`」（≈5 行） |
| 🟢 低 | probe-cpu 首采样偏差 | 模块加载时取基准快照，加载与首次采样间隔大则分母偏大、数值偏低（实测影响小） | 可不管；要精确则首次 `sample()` 返回空数组 |

**补充：M1 实施时会撞到的 2 个技术坑**（监工复核，提前说能省两小时）

| # | 坑 | 为什么会撞 | 怎么绕 |
|---|---|---|---|
| **A** | **pnpm `isolated` 链接下，未在 `package.json` 声明的包 `import()` 会直接失败** | M0 实测 `.modules.yaml` → `nodeLinker: isolated`：包只能访问**自己声明过**的依赖。若 cli 不声明 `@zhizhi/probe-cpu`，`import('@zhizhi/probe-cpu')` 会在 **catch 之前**就 `ERR_MODULE_NOT_FOUND` | 清单里的插件**仍要在 `cli/package.json` 保留依赖声明**；想表达"可缺失"就用 `optionalDependencies`。**验收测试操作的是「清单数组」（不是 package.json）**，所以"从清单去掉"能过 |
| **B** | **各插件的 `manifest.json` 当前没在 `exports` 里** | 三个插件的 `package.json` 只导出了 `"."`，所以 `import('@zhizhi/probe-cpu/manifest.json')` 会报 `ERR_PACKAGE_PATH_NOT_EXPORTED` | 各插件 `exports` 加一条 `"./manifest.json": "./manifest.json"`；或用 `import.meta.resolve()` 取入口路径再拼相对路径 |

> ℹ️ 另：M1 第 4 步把总线接通后，`bus` 在 M1 期内是「**在岗但无订阅者**」（`emit` 找不到 handler 只 return）—— 正常，真正的消费者（`rule` / `persona`）M2 / M5 才出现。

**结论：M0 通过。** 代码质量高于同类骨架，四条硬约束全守住。
M1 的最大风险（静态 import 过不了"删插件"验收）**已由用户在报表第三节的 M1 拆解中提前覆盖，方案正确**；只剩上面 2 个实施细节坑，提前知道即可。
