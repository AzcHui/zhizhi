# 让电脑活起来 · 互动与情绪价值功能评估

> 评估日期：2026-10-14　机器：H610P4 AIO / i5-12450H / Intel UHD / 32GB DDR4-2667 / Win11 25H2
> 前提文档：《让电脑活起来-系统生命体征助手方案.md》

---

## 一、结论先行

**你提的这四个功能，我的总评是：三个建议做，一个要降级，另外顺序必须改。**

| 你的想法 | 我的判断 | 一句话理由 |
|---|---|---|
| 👍 点赞 / 评论 | **做，但"评论"降级成按钮** | 打字成本比点按钮贵 100 倍；而且**点赞的真正价值不是"了解你"，是"教它闭嘴"** |
| 🧠 记住喜好 / 人物画像 | **做「行为画像」，「兴趣画像」别做** | 行为数据全在你本机、不涉隐私；兴趣画像要翻你的文件，风险大于收益 |
| 🤚 鼠标反复划 = 摸摸 | **做，但必须克制** | 技术很便宜（**但别用鼠标钩子，见第五节**）；真正的难点是"不能有求必应" |
| 💗 情绪价值 | **做，而且是核心** | 但**别让它当舔狗**——见第四节，这条是整份文档最重要的部分 |

**一句话**：这些功能加起来，就是这套东西从「报警器」变成「活物」的全部秘密。**但它们也会把你最容易翻车的那件事（通知疲劳）放大**——所以下面每一条我都要配一个"克制条款"。

## 二、逐项评估

### 1️⃣ 👍 点赞 / 👎 点踩 / 🔇 静音

**做。但请先把它的定位从"记录喜好"改成"反馈闭环"。**

你的原始想法是「点赞 → 它了解我的喜好」。这个方向对，但**只对了一半**——真正决定生死的不是 👍，是 👎 和 🔇。

| 动作 | 表面含义 | **实际作用（更重要）** |
|---|---|---|
| 👍 | 这条我喜欢 | 强化**这一类**消息的表达方式 |
| 👎 | 这条不对 | **降低这类消息的频率 / 换个说法** |
| 🔇 | 别再说了 | **永久静音这个事件类型** |

**核心认知**：

> **没有反馈按钮，你只有两个选项：让它一直烦你，或者手动关掉全部通知。
> 有了反馈按钮，第三个选项出现了：它自己学会什么该说、什么不该说。**
>
> **这就是"活"——它是宠物学会闭嘴的唯一途径。**

一个会看眼色的助手，比一个话多的助手像活的 100 倍。而"看眼色"的能力，只能靠你喂它 👎。

### ⚠️ 「评论」要降级 —— 别做自由输入

自由文本框看起来很美好，但：

- **打字成本极高**。你正忙着写代码，弹个气泡还要你打字评论？你会直接点 X。
- **数据质量反而差**。自由文本你还得自己分析语义，又得请模型，又慢又贵。

**替代方案**：点 👎 之后，弹出 **3 个固定原因按钮**——

```
  ┌─────────────────────────────┐
  │  这条提醒不太行，是哪一种？    │
  │  [ 太频繁了 ] [ 说错了 ] [ 烦  ] │
  └─────────────────────────────┘
```

- 比自由输入**便宜 100 倍**（一次点击 vs 一段打字）
- 数据**天然结构化**，直接就能用来调权重，连模型都不用请
- 真想要"评论"，留一个**单独的入口**（比如托盘右键 →「对它说点什么」），你想写的时候去写，而不是每次冒泡都提示你

### 2️⃣ 人物画像 —— 分两种，一种做，一种坚决别做

这是最容易做过头的地方。我把它们切开：

| | 行为画像 ✅ **建议做** | 兴趣画像 ❌ **别做** |
|---|---|---|
| 数据来源 | 它自己记录的事件日志（纯本地） | 你的文件、浏览器历史、聊天记录、剪贴板 |
| 内容 | 「你 14:00–18:00 最活跃」「你对内存类提醒点了 4 次赞，对磁盘类点了 3 次踩」「你最近摸摸它 12 次」 | 「你喜欢电车」「你在看劳动仲裁的事」「你女朋友叫什么」 |
| 隐私风险 | **零**（数据是它自己产生的） | **高**（等于让一个程序偷看你的一切） |
| 实现成本 | 一个 JSON 文件 | 要读文件 + 语义分析 + 模型 |
| 实际效果 | **很好**——它开始挑对的时间、对的语气说话 | **很尬**——像个偷翻你东西的朋友 |

**为什么"兴趣画像"要坚决否掉？**

1. **它不是你的需求。** 你要的是"电脑活起来、干活有劲"，不是"有个东西分析我"。后者是另一件事（而且市面上已经有）。
2. **做出来会很不舒服。** 想象它冒一句「我注意到你最近经常看电车」，你会脊背发凉，而不是觉得贴心。
3. **它直接违背我们刚立的规矩**——我在方案里说过「只解释和建议，不动手」。同理，**只观察机器，不窥视你**。这条边界守住了，这东西才值得你长期开着。

**而且有个好消息**：**行为画像本身就足以产生"养成感"。** 见第六节的"亲密度"设计——**你不需要知道"我喜欢什么"，只需要知道"我对什么有反应"**，后者的数据量级小 1000 倍，效果却更好。

### 3️⃣ 🤚 摸摸（鼠标反复滑动）

**做，而且我很喜欢这个想法**——它是"活"最直接的证据：**一个会回应你的东西，比一个只汇报的东西更像生命。**

但两个技术点和一串设计陷阱，必须先说清楚。

#### 技术点（第五节有实测依据）

- ❌ **不要用全局鼠标钩子**（`WH_MOUSE_LL`）——联网核实后**明确排除**，理由见第五节
- ✅ **用 `GetCursorPos` 定时轮询**（50ms 一次）——CPU 开销约等于零，而且**不会被火绒 HIPS 盯上**

#### "摸摸"的判定算法（关键是**天然防误判**）

```
判定条件：1.5 秒窗口内
  ① 光标位移始终在 80px 半径内（在"原地"）
  ② 方向反转 ≥ 3 次（来回划）
  ③ 持续时间 ≥ 0.8 秒
```

**为什么这个条件很好？** 因为**正常使用鼠标几乎不可能触发它**——

- 正常移动鼠标：一路直线，**0 次反转** → 不触发
- 拖选文本 / 拖窗口：有反转但**位移远超 80px** → 不触发
- 来回切两个窗口标签：**位移超 80px** → 不触发

**只有你"故意在某个位置来回揉"才会命中。** 这比什么"摸头热区"精确得多，也不需要你划定区域。

#### 设计陷阱（这条比技术更重要）

> **摸摸绝不能有求必应。如果摸一下就叫，那是按钮，不是宠物。**

正解是**把它挂到"状态机"上**——同一个动作，不同的状态，不同的反应：

| 它的状态 | 你摸它 → 反应 |
|---|---|
| **开心**（CPU 低、空间宽裕） | 冒个小爱心 / 「嗯…」 |
| **累**（连续高负载 2 小时） | 「让我歇会儿…」 |
| **睡着**（你离开 30 分钟） | 先"惊醒"，再「唔…？」 |
| **生气**（你三天没理它 / 连着点了几次踩） | 「哼。」（然后别过头——其实是不反应） |

**同一个动作有不同反馈，它才像有内心的东西。** 固定的"摸一下→跳一下"，玩两天就腻。

#### 还有一个必须遵守的：**摸摸的反馈不能是 Toast**

- Toast 是**强提醒**（有声音、进通知中心、占屏）
- "摸摸"是**装饰性互动**，被 Toast 弹出来挡在屏幕中间会非常难受

**正解**：用**小气泡 / 托盘图标变化**（比如图标眨眼、托盘弹出一个小气泡），**无声、不打扰、2 秒自动消失**。这就是为什么我建议**保留托盘图标**——不只是个形象，它是"低成本表达通道"。

### 4️⃣ 💗 情绪价值 —— 这是核心，但有个反直觉的关键

**做。而且我认为这才是整件事的灵魂**——你说"上班都觉得有趣了"，靠的就是它，不是靠 CPU 监控。

但我要给你一条**反直觉的建议**，而且我觉得它跟你特别合：

> ### 🚫 别让它当舔狗。

一个只会说「你真棒！」「太厉害了！」的宠物，**三天就腻**。因为那种话没有信息量，你知道它是程序写的。

**真正有情绪价值的，是"有自己态度"的东西：**

| 舔狗版 ❌ | 有态度版 ✅ |
|---|---|
| 「主人真棒！」 | 「这破代码你改了 12 次了，要不要先睡一觉？」 |
| 「内存不足了哦~」 | **「又来了。这个月第 7 次。还是 Chrome。我都不想说了。」** |
| 「加油！」 | **「你连着坐 3 小时了。我不催你，但我记着。」** |
| 永远笑脸 | 累的时候真的**话少**，被踩多了**会冷淡** |

**为什么这条特别适合你？**

你自己说过，你讨厌被迎合，宁愿对方直接说实话。**那你养的宠物也不该是个舔狗。** 一个会吐槽你、会因为你忘关 Chrome 而无奈、会因为你不理它而冷淡的东西——**它才像有生命，因为生命有自己的意志**。

**而且这在技术上更简单**：情绪 = **状态机 + 台词池**，**完全不需要模型**。

- `mood` 字段（0~100）+ 一个状态表 + 每个状态 20 条台词
- 这就是 80% 的情绪价值，**零依赖、零延迟、零成本**
- 模型只在 P2 之后**锦上添花**（生成"没写过的新话"），不是必需品

> 💡 换句话说：**你先用纯规则版就能体验到大部分乐趣。** 这符合你要的"简洁非过度工程化"。

## 三、这为什么会放大"通知疲劳"风险

原方案里最危险的失败模式是**通知疲劳**（我估过：三天你就把它关了）。加了互动之后，**这个风险变大了**，因为：

- 互动好玩 → 你会想"多弹一点吧" → 一个月后你被自己养的东西烦死
- 而且**互动类反馈（摸摸、情绪）本质上不是"提醒"**，不该走提醒通道

**所以加三条新规矩**（补进原方案）：

| 规矩 | 说明 |
|---|---|
| **分通道** | 提醒走 Toast（强）；互动/情绪走小气泡 + 托盘（弱）。**永不混用** |
| **互动不需要"建议"** | 摸摸反馈就一句俏皮话，**别附带"建议关闭 Chrome"**——那就不萌了 |
| **互动总预算** | 每天主动说话有上限（比如 10 次）。**超了就只记日志不弹** |

## 四⚠️ 一个容易忽略的坑：它会跟你的"安全哨兵"打架

联网核实出来的一个细节（有实证来源）：

> **从 PowerShell 弹 Toast，通知的署名会显示为「Windows PowerShell」**——因为普通进程没有已注册的"应用身份"，只能借用 PowerShell 的。

**这为什么是个问题？**

你这台机器有明确的安全史（ScreenConnect + 挖矿，5 处持久化残留是我 10/10 亲手挖出来的）。**你花大力气做"安全哨兵"，结果你自己的助手弹出来的窗口写着「Windows PowerShell」**——万一哪天它弹一句"新增了可疑自启项"，你会怀疑这是不是又一个木马 😅

**两个解法**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A（推荐）** | 给它注册自己的 **AppUserModelID**（注册表 + 一个带 AUMID 的快捷方式），署名变成「系统助手」之类 | 十几行配置，一次搞定 |
| **B** | 接受显示为「Windows PowerShell」，但**在 README 里给自己留个说明** | 零成本，但会膈应自己 |

**而且顺带一个必然结果**：**你自己的助手会被你自己的火绒盯上**（常驻 + 读注册表 + 弹通知，形状很可疑）。这跟你之前清的 `RuntimeHost.exe` 是同一类行为特征。👉 建议**提前把它加进火绒的信任区**，并且**别给自己起一个可疑的名字**（原方案里我已经提醒过：别叫 "Windows System Health" 这种——你这台机器上刚清掉的木马任务就叫这个名 😄）。

## 五、技术核实结果（对照我们之前的技术栈）

### ✅ Toast 能带按钮 —— 但要用对方式

| 激活类型 | 能否免注册使用 | 说明 |
|---|---|---|
| `protocol` | ✅ **可以** | 按钮 `arguments` 里写自定义协议（如 `alive://like/123`），再在注册表注册该协议指向处理脚本。**这是免 UWP 注册的可行路线** |
| `foreground` / `background` | ❌ 不行 | 需要 AppX 清单 + 应用身份注册，普通 Node 进程做不到 |

**所以 👍 按钮技术上可行**，但需要额外做一次"协议注册"。
👉 **但我不建议 P2 就上它**——见第六节，**先用托盘右键菜单收集反馈**，零风险、当天能跑，验证过"你真的会点赞"再上 Toast 按钮。

### ❌ 鼠标钩子：明确排除（有依据）

联网核实的关键结论（多来源一致）：

> 「除非你真需要**每毫秒都捕获**或**跨进程精确拦截点击**，否则不用钩子。
> **全局钩子开销大、易被杀软拦截**；.NET 5+ 在非管理员权限下注册 `WH_MOUSE_LL` 经常**静默失败**。」

对你的场景——**我们只需要知道"光标在哪儿、有没有来回划"**，不需要拦截任何东西：

| | 全局钩子 ❌ | `GetCursorPos` 轮询 ✅ |
|---|---|---|
| CPU 开销 | 每次鼠标事件都回调 | 50ms 一次取坐标，约等于零 |
| 火绒 HIPS | **容易被盯上**（输入监听是杀软重点监控行为） | 无感 |
| 你的特殊处境 | **你刚清完木马，最不该引入"输入监听"这种东西** | 干净 |
| 权限 | 非管理员常静默失败 | 不需要 |
| 精度 | 更高 | **对本场景完全够用** |

👉 **结论：用轮询。** 也就是说——**这个最"高科技"感的功能，实现手段反而是最朴素的。**

## 六、修订后的阶段路线 ⭐（这里我改了你的顺序）

原方案是 `P0 → P1 → P4`。你的新想法进来之后，**顺序必须改**：

| 阶段 | 内容 | 改动 |
|---|---|---|
| **P0** | 采样 + 四道闸门 + Toast | 不变 |
| **P1** | **进程归因**（"Chrome 吃了 2.1G"） | 不变 |
| **P2** | 🆕 **反馈闭环**（👍👎🔇，先走**托盘右键菜单**） | ⬆️ **从原 P5 提到这里** |
| **P3** | **记忆 / 行为画像**（事件历史 + z-score 基线） | 原 P3 |
| **P4** | **安全哨兵** | 不变（你最需要） |
| **P5** | 🆕 **情绪系统**（mood 状态机 + 台词池）+ **摸摸** | 合并、提前 |
| **P6** | 接 Ollama（模型只做"表达"）+ 自定义 AUMID | 原 P2 后置 |

### 为什么要把"反馈闭环"提到 P2？

因为**它是后面所有"学习"的前置条件**：

```
没有 👍👎🔇  →  它无法知道你说得好不好  →  记忆只能在"数量"上累积，
                                          语气/时机永远调不准
有了 👍👎🔇  →  每一次点击都在教它  →  记忆才真正变成"懂你"
```

**先有反馈，再有记忆。** 顺序反了，P3 的记忆系统就只是"记流水账"，长不出"养成感"。

### 为什么"情绪系统"可以提到 P5（和摸摸一起）？

因为它**不需要模型**（状态机 + 台词池），可以早早享受到，又**不依赖 P6 的模型**。

## 七、🆕 一个具体的设计：亲密度（养成感的引擎）

你要的"记住我的喜好、了解我"，落到实现上，**一个数字就够了**：

```
亲密度 trust: 0 ~ 100    （存本地 JSON）

+3  点了 👍
+1  点开通知看了（不是直接划掉）
+2  摸了摸它
-5  点了 👎
-8  点了 🔇
-1  一条通知被忽略（超过 10 分钟没看）
+2  和它对话（P6 之后）
每天 -2  （不互动就缓慢下降）
```

**它驱动什么？**

| 亲密度 | 它的表现 |
|---|---|
| **80~100** | 话多、活泼、主动说俏皮话、愿意吐槽你 |
| **40~79** | 正常，说正经话为主 |
| **10~39** | 话少、冷淡、只用必要提醒 |
| **0~9** | 只报警（功能性），**几乎不说话**——「它不理你了」 |

**为什么这个设计好？**

1. **它把"了解你"变成了"和你互动"**——不是它偷看你，是**你亲手养出来的**。这才是宠物和监控软件的区别。
2. **它天然实现了"沉默"原则**：你不理它 → 它安静下来。不需要写复杂的规则。
3. **一个 JSON 文件，零依赖**。
4. **它天然产生"我想让它开心点"的心理**——这就是你说的"上班都觉得有趣了"。

> ⚠️ **但有一个底线**：**别做成"点赞换奖励"的抽卡/签到游戏**（就是某些 App 那套）。
> 你的目标是"干活有劲"，不是"被系统绑架注意力"。**它该是个室友，不是个运营活动。**

## 八、我的总建议

### ✅ 建议做的（按这个顺序）

1. **反馈按钮（👍👎🔇）** — 先走托盘右键，零风险
2. **行为画像**（纯本地事件日志）
3. **情绪系统**（mood 状态机 + 台词池，**不用模型**）
4. **亲密度**（一个 JSON 数字）
5. **摸摸**（`GetCursorPos` 轮询 + 随机区间）

### ⚠️ 降级做的

- **"评论"** → 改成 3 个固定原因按钮；自由输入留一个单独入口
- **Toast 按钮** → 先用托盘菜单替代，验证后再上

### ❌ 明确别做

| 别做 | 理由 |
|---|---|
| **兴趣画像**（读文件/浏览器历史/聊天） | 隐私 + 越界 + 效果尬。**只观察机器，不窥视你** |
| **"点赞换奖励"式的签到机制** | 会变成绑架注意力的运营活动，与初衷相反 |
| **有求必应的摸摸**（摸一下就必跳） | 那是按钮，不是宠物 |
| **自动修复动作**（杀进程/删文件） | 原方案的边界，不因加了互动而放开 |
| **让互动走 Toast 通道** | 强提醒 vs 弱互动，必须分通道 |

### 🎯 我最想让你记住的一句话

> **这些东西的价值不在"功能多"，而在"它有分寸"。**
>
> 一个知道你上班时间不吵你、记得你第 7 次忘关 Chrome、被你骂过就学会少说话、
> 摸它会开心但累了会说"让我歇会儿"的东西——
> **它的迷人之处，全部来自"它不是随叫随到的"。**
