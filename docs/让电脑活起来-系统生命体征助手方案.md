# 让电脑「活起来」——系统生命体征助手方案

> 实测日期：2026-10-14　目标机器：H610P4 AIO / i5-12450H / Intel UHD / 32GB DDR4-2667 / Win11 25H2

---

## 一、结论先行

**这个方向比桌宠好得多，而且我更喜欢它。** 理由：

| | 桌宠 | 生命体征助手（本方案） |
|---|---|---|
| 价值 | 情绪价值（看着开心） | **情绪价值 + 实用价值**（真的有用） |
| 与你已有积累的关系 | 从零开始 | **这个会话里我已经给你写了 32 个系统探测脚本**——那全是这套东西的零件 |
| 技术难度 | 中（要学 Tauri/窗口机制） | **低**（采集+判断+发通知，全是你会的东西） |
| 「活」的感受来源 | 形象 + 动作 | **它会说话、有记忆、会挑时机** |

**一句话**：桌宠是「给电脑贴个贴纸」，这个方案是**「给电脑装上神经系统」**——它会疼、会累、会记得、会主动跟你说点什么。

技术难度 **低**，工作量 **P0 只要半天**，而且**可以零依赖起步**。

## 二、最核心的一个认知（决定成败）

> ### 监控不需要模型，只有「表达」需要模型。

这是整个方案的基石。展开说：

| 层 | 需不需要 LLM | 为什么 |
|---|---|---|
| **感知**（读 CPU/内存/磁盘） | ❌ **不需要** | 这是取数，`Get-Counter` / `systeminformation` 就够了，毫秒级 |
| **判断**（多少算异常） | ❌ **不需要** | 阈值比较是确定性的。**`内存 > 85%` 判得比任何模型都准、都快、都免费** |
| **表达**（怎么说出来） | ✅ **需要** | 「内存 87%，Chrome 占 2.1G」→「内存有点挤，Chrome 那个大胃王吃了 2.1G，要我说它两句吗？」——**这才是模型的价值** |
| **通知**（弹出来） | ❌ 不需要 | 调 Windows API |

### ❌ 致命反例：每 5 秒轮询一次模型

如果每采样一次就问一次模型，你请来的这个「监工」会变成**整台机器上最吃资源的东西**。

实测佐证（刚跑的，本机此刻内存 Top）：

```
Memory Compression   2992 MB
WorkBuddy             631 MB   ← 我自己（另一个实例还有 336MB，合计 967MB）
Code (VSCode ×3)      520 + 451 + 433 = 1404 MB
msedge                385 MB
explorer              383 MB
```

**你的监控程序要是也占 1GB、还每次都推理，那它就活成了自己最讨厌的样子。** 😅

### ✅ 正确做法：事件驱动

```
每 5 秒：采样 → 纯规则判断（耗时 < 1ms，零推理）
                              │
                    ┌─────────┴─────────┐
                 正常                  异常（且过了冷却期）
                    │                     │
              静默写日志                  调模型生成人话（2~4s）
                                          │
                                      弹 Toast
```

**平时零 CPU 推理开销，只在「值得说」的时候才唤醒模型。** 这同时解决了你集显跑模型慢的问题——2 秒的延迟被藏在「它不是秒回，是在思考」里，反而更像活的。

## 四、四层架构（见上方架构图）

### L1 感知层（每 5 秒，成本 ~0）

| 指标 | 来源 | 用途 |
|---|---|---|
| CPU 总占用 + 单核 | `Get-Counter` | 判断「在负载」还是「空转」 |
| 内存：物理 / 提交 / **压缩** | `Win32_OperatingSystem` | 内存告警（注意「Memory Compression」这个隐形大户） |
| 磁盘空间 C/D/E | `Win32_LogicalDisk` | 空间告警（你的 C 盘 118.9G / 剩 52.4G） |
| 磁盘 IO 读写速率 | `Get-Counter` | 卡顿归因（SSD 是 **SATA**，更容易吃满） |
| 网络上下行 | `Get-Counter` | 异常外联检测（**安全哨兵要用**） |
| **进程 Top5（内存/CPU）** | `Get-Process` | **归因——「谁干的」比「多少」重要 100 倍** |

### L2 判断层（毫秒级，纯规则）

**四道闸门，缺一不可**：

| 闸门 | 规则 | 解决什么问题 |
|---|---|---|
| ① **静态阈值** | 内存 > 85%、CPU > 90%、C 盘 < 10% | 基本盘 |
| ② **持续判定** | 超标**持续 2 分钟**才报 | **防毛刺**——编译时 CPU 飙 100% 是正常的，不能每次都喊 |
| ③ **基线偏移** | 对比自己的历史（z-score） | 发现「不寻常」而不只是「高」——**这是「活」的智力表现** |
| ④ **冷却期** | 同一事件 15 分钟内只报一次 | **防打扰**——没有这道闸门，三天你就把它关了 |

### L3 表达层（模板 0ms / 模型 2~4s）

**分级降级策略**：

```
有模型且在运行？ → 生成人话（2~4s，占 2%）
      ↓ 否
模板库随机挑一句 → 立即弹（0ms，占 98%）
```

**关键**：模型不可用时**必须能自动降级到模板**，否则 Ollama 没启动 = 整个系统哑巴。

### L4 通知层（零依赖）

已验证可行，路线：

```powershell
[Windows.UI.Notifications.ToastNotificationManager, Windows.UI.Notifications, ContentType=WindowsRuntime] | Out-Null
$xml = New-Object Windows.Data.Xml.Dom.XmlDocument
$xml.LoadXml($toastXml)
[Windows.UI.Notifications.ToastNotificationManager]::CreateToastNotifier($appId).Show((New-Object Windows.UI.Notifications.ToastNotification $xml))
```

- **AppID 是唯一需要调的地方**：可以复用已注册的（如 PowerShell 自己的 AppID），或建一个带 AppUserModelID 的快捷方式。若遇阻，备选方案是装 `BurntToast` 模块（它把 AppID 问题处理好了）。
- Node 侧只需 `child_process` 调一次 PowerShell——**加一个 npm 包都不需要**。

## 五、「活」从哪来（比监控本身更重要）

这是我最想跟你聊的部分。**监控本身一点都不难，难的是让它「活」。**

我认为「活」= **记忆 × 主动 × 沉默**。

### 1️⃣ 记忆 —— 没有记忆的提醒是闹钟，有记忆的提醒是关系

| 没记忆 | 有记忆 |
|---|---|
| 「内存占用 87%」 | 「**这是你这个月第 7 次**内存上 90% 了。每次都怪 Chrome。」 |
| 「C 盘剩余 8%」 | 「你上次清完 C 盘，**3 天就又满了**。这次我盯着。」 |
| 「CPU 95%」 | 「**上周这个点你也在编译**。是同一个项目吗？」 |

实现：一个本地 JSON + SQLite 就够。**记录「事件 + 时间 + 归因进程」，就是它的海马体。**

### 2️⃣ 主动 —— 不是只被动响应，也会自发起行为

纯响应式的系统是「报警器」。要有生命感，它得**自己想说点什么**：

- 「你连着坐了 **3 小时**，其中 2 小时 47 分在同一个文件上。」
- 「今天你编译了 **37 次**。第 12 次之后就没成功过，要不要看看？」
- 「凌晨 1:42，你还在写代码。我不催你，但我记着。」

### 3️⃣ 沉默 —— 最重要，也最容易被忽略

> **一直叫的不像活的，像闹钟。有分寸才像活的。**

必须实现：
- **冷却期**：同一问题 15 分钟只提一次
- **静默时段**：全屏应用 / 演示 / 游戏时闭嘴（检测全屏窗口）
- **静默分级**：日志里记，但**不弹**——「我知道，但我选择不说」
- **主动降噪**：如果某个告警你连续 5 次忽略，它学会收声（甚至可以自己说：「这个我提醒过 5 次了，以后不烦你了」）

> 💡 **这一条其实是「活」的最高级形态：它有自己的判断和克制。** 这也是为什么我建议给它一个「情绪/状态」字段——CPU 低+空间宽裕 = 它心情好；连续高负载 2 小时 = 它「累」。

## 六、🎯 杀手级功能：安全哨兵（结合你的经历）

**这是本方案对你个人最有价值的部分。**

你这台机器有明确的威胁史：**ScreenConnect + .NET 进程镂空挖矿**（火绒 6/23、6/30 报过），我 10/10 还在你系统里挖出了 5 处持久化残留（3 个 `Windows System Health*` 计划任务 + 2 处 `WinSysCache` 的 `RuntimeHost.exe` 注册表 Run 项）。

**那些东西之所以能潜伏，就是因为没有人实时盯着「新增了什么」。** 这个助手可以补上这块：

| 哨兵能力 | 怎么做 | 对应你踩过的坑 |
|---|---|---|
| **新增自启项告警** | 基线快照 + 对比 `HKCU/HKLM ...\Run`、启动文件夹 | `WinSysCache` 就是写进 Run 的 |
| **新增计划任务告警** | 对比 `Get-ScheduledTask` 全量快照 | `Windows System Health` 三个任务 |
| **可疑进程模式** | CPU 高 + 无窗口 + 路径在 `Temp`/`AppData` | 挖矿进程的典型特征 |
| **未签名可执行** | 检查新进程的数字签名（像我们查 `fdm.exe` 那样） | FDM 未签名 |
| **异常外联** | 新出现的对外连接 + 目的端口 | ScreenConnect 的回连 |
| **IOC 复扫** | 定期跑你已有的 `sys_ioc.ps1` 逻辑 | 直接复用 |

组合成一句人话：

> 「停一下。新增了一条自启项：
> `C:\Users\zzzzj\AppData\Roaming\xxx\yyy.exe`，**未签名**。
> 模式我不喜欢。要我打开文件位置给你看吗？」

**这一句的价值，抵得上前面所有功能。** 你请了个 24 小时不睡的保安。

## 七、技术选型（保持简洁）

| 组件 | 选择 | 理由 |
|---|---|---|
| 运行时 | **Node.js v22.22.2** | 你最熟；Python 在你机器上不可用 |
| 采集 | **`systeminformation`**（1 个 npm 包） | 一个包覆盖 CPU/内存/磁盘/网络/进程，省得自己拼 |
| 通知 | **PowerShell 桥**（0 依赖） | WinRT 已实测可加载 |
| 存储 | **JSON 文件**（0 依赖） | 事件日志 + 记忆。数据量小，不需要数据库 |
| 模型 | **Ollama + `qwen3.5:2b`** | P2 阶段才装；`keep_alive: 0` 控制内存 |
| 常驻 | **任务计划程序**（登录时启动） | ⚠️ **任务名要起清楚**（别叫 "Windows System Health" 这种——你自己刚清理过同名的木马任务 😄） |

**总依赖：1 个 npm 包 + 1 个可选模型。** 这就是我理解你要的「简洁非过度工程化」。

## 八、MVP 与分阶段

### P0 · 半天可跑（严格按这个起步）

```
✅ 每 5 秒采样 CPU / 内存 / 磁盘
✅ 四道闸门（阈值 + 持续2min + 冷却15min）
✅ 触发时弹 Windows Toast（模板台词）
❌ 不接模型、不做记忆、不做安全哨兵
```

跑通 P0，你已经能收到「内存有点挤」的提醒了。**先验证「它烦不烦你」——这是最容易翻车的地方。**

### 分阶段（每阶段独立可用）

| 阶段 | 加什么 | 价值 |
|---|---|---|
| **P0** | 采样 + 规则 + Toast | 基本盘，半天 |
| **P1** | **进程归因**（"Chrome 吃了 2.1G"）+ 点击通知可操作 | 从「报警」变「有用」，收益最大的一步 |
| **P2** | 接 Ollama：模板 → 人话 | 从「有用」变「活」 |
| **P3** | **记忆系统**（历史 + 习惯 + z-score 基线） | 从「活」变「懂你」 |
| **P4** | **安全哨兵**（自启项/计划任务/可疑进程） | 🎯 你最需要的那块 |
| **P5** | 主动性 + 情绪状态 + 静默学会 | 「有分寸」 |

> 推荐节奏：**P0 → P1 → P4**（先把「有用 + 安全」做扎实），再回头做 P2/P3 的「活」。**别一上来就接模型 —— 阈值判断已经解决 90% 的问题。**

## 九、风险与实话

| 风险 | 说明 | 对策 |
|---|---|---|
| **通知疲劳** | 最大的失败模式。三天就被你关掉 | 冷却期 + 持续判定 + 分级；**宁可少说，不可多说** |
| **模型延迟暴露** | 2~4 秒才出话，显得笨 | 事件驱动 + **降级到模板**；或先弹「...」再替换 |
| **监控程序自身吃资源** | 讽刺但常见 | 采样用轻量 API，**绝不轮询模型**，进程本身目标 < 50MB |
| **温度读不到** | BIOS 不暴露 ACPI 热区 | 需 LibreHardwareMonitor 辅助（P5 可选，不强求） |
| **误判为可疑程序** | 你自己的常驻脚本可能被自己的杀软盯上 | 写好签名/说明；**你刚清理过木马，别再引入形状可疑的东西** |
| **Windows 已有的重叠** | 任务管理器、存储感知、安全中心已有部分能力 | 差异化的**唯一**理由是「说人话 + 有记忆 + 主动关心」——做不到这三点就没意义 |

### 明确不做

- ❌ Prometheus / Grafana 那套（服务器方案，家用机是过度工程化）
- ❌ 自动执行修复动作（杀进程、删文件）——**只解释和建议，不动手**。这是安全边界，也让它的角色更「诚实」
- ❌ 每采样一次问一次模型
- ❌ 做仪表盘/图表（任务管理器已经有了，它该做的是「说话」，不是「画图」）
