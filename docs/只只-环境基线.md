### ⚠️ 最重要的一条：`node_modules` 里的 `.ts` 跑不了

Node 的原文报错：

```
Error [ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING]:
Stripping types is currently unsupported for files under node_modules,
for "D:\MyProjects\zhizhi\node_modules\__ts_probe\lib.ts"
```

**那 pnpm workspace 的插件为什么能跑？** —— 因为**软链被 realpath 展开了**：

```
import.meta.resolve('@zhizhi/probe-cpu')
  → file:///D:/MyProjects/zhizhi/packages/plugins/probe-cpu/src/index.ts   ← 真实路径，不在 node_modules 下
```

磁盘上它确实是个软链：

```
packages/cli/node_modules/@zhizhi/probe-cpu
  -> /d/MyProjects/zhizhi/packages/plugins/probe-cpu
```

Node 默认 `preserveSymlinks=false`，解析模块时把软链展开成真实路径，于是**绕开了** `node_modules` 限制。

> ⚠️ 这是「**恰好能跑**」，不是「设计如此」—— 所以下面那条推论必须记住。

## 四、这个发现对架构的直接影响 ⭐

| # | 结论 | 影响 |
|---|---|---|
| 1 | **插件不能是「真装在 `node_modules` 里的 `.ts` 包」** | 一旦从 npm 装进 `node_modules`，`.ts` 直接炸 |
| 2 | **S3 动态加载的形态被限定了** | 只能「扫 `pluginsDir` 目录 + 按路径 `import()`」，**不能是「npm install 一个插件包」** |
| 3 | 若将来要把插件发到 npm | 必须是**编译后的 `.js`**（或以整个目录分发），不能发 `.ts` |
| 4 | 我们自己的 workspace 插件没事 | 软链 → realpath 落在项目内，实测可加载 |
| 5 | 项目对 Node 版本有硬要求 | `>=22.18`（type stripping 默认开启的版本）。Node 20 用户跑不起来 —— **M9 开源时 README 必须写明** |

> 换个说法：**我们享受了「零构建」的好处，代价是「插件分发形态受限」。**
> 这笔账要在 M9（开源准备）时对外讲清楚，别让贡献者踩坑。

## 五、已知坑（踩过，别再踩）

| # | 现象 | 处理 |
|---|---|---|
| 1 | `tsc` 报 `TS2688: Cannot find type definition file for 'node'` | pnpm 11.21.0 偶发不在根 `node_modules/@types` 建链接。`--force` 与 `pnpm add` **都无效** → **`rm -rf node_modules && pnpm install`** |
| 2 | 想 import 相对文件 | 必须写全扩展名 `./x.ts`（Node ESM 不做扩展名解析）；tsconfig 已开 `allowImportingTsExtensions` 兜住类型检查 |
| 3 | 想用 `enum` / `namespace` / 构造函数参数属性 | ❌ 不行。`erasableSyntaxOnly` 会拦下（这些语法无法「擦除」）→ 用 `const` 对象 + 联合类型替代 |
| 4 | 在插件里想 import `@zhizhi/core` | ❌ 铁律② 禁止。只能 import `@zhizhi/plugin-sdk`，core 的**类型**由 SDK 转发出来 |

## 六、怎么重新复核（复制粘贴即可）

```bash
# 版本
node -v
node -p "process.features.typescript"     # 应为 'strip'
pnpm -v
./node_modules/.bin/tsc -v
pnpm list -r --depth 0                    # 实际安装的依赖树

# 动态加载能力（M1 关键）
cd packages/cli && node --input-type=module -e "console.log(import.meta.resolve('@zhizhi/probe-cpu'))"

# node_modules 限制（应报 ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING）
mkdir -p node_modules/__probe && printf 'const x: number = 1;\nexport default x;\n' > node_modules/__probe/a.ts
node -e "import('./node_modules/__probe/a.ts').catch(e=>console.log(e.code))"
rm -rf node_modules/__probe
```

**版本变更时**（Node / pnpm / TypeScript 升级后）：重跑本节命令 → 更新本文件 → 在《开发进度报表》更新日志记一行。
