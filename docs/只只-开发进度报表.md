## 三、下一步动作（M0 拆解，可直接照着做）

| 步骤 | 做什么 | 备注 |
|---|---|---|
| 1 | 建仓库根目录 | 建议 `D:\MyProjects\zhizhi`（**待你确认**） |
| 2 | 初始化 pnpm workspace | `pnpm init` + `pnpm-workspace.yaml` |
| 3 | 建 `packages/core` | `bus / scheduler / store / gates / dispatcher / registry / types` 骨架（**types 是唯一跨插件数据结构定义处**） |
| 4 | 建 `packages/plugin-sdk` | `define-probe / define-rule / define-persona / define-channel` + `manifest` |
| 5 | 建 `packages/plugins` | `probe-cpu` / `probe-mem` / `probe-disk`（**用 SDK 写，不许有内核特权**） |
| 6 | 建 `packages/cli` | `main.ts`：加载插件 → 采样 → 打印 JSON |
| ✅ | **验收** | `pnpm --filter cli start` 后，终端每 5 秒出现一行指标 JSON |

**M0 的四条硬约束（写在前面，避免返工）**：
1. `core` **零 UI 依赖** —— 它必须能被 `cli` 和未来的 `app` 同时消费
2. **插件之间禁止互相 import** —— 只能走 `core/bus`
3. **官方插件也用 `plugin-sdk`** —— 不许有"内核特权"
4. **插件加载失败不影响内核** —— 独立 try/catch + `discovered→active→failed` 状态机
