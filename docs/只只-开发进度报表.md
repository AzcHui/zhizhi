## 三、下一步动作（M2 拆解，可直接照着做）

**M2 目标**：**四道闸门 + 分通道** —— 让只只从「一直在看」变成「**该说才说**」。

**验收标准（三条，缺一不可）**：
1. 编译时 CPU 飙到 100% → **不报警**（防毛刺）
2. 连续超阈值 **2 分钟** → **才报警**
3. 同一事件 **15 分钟内只报一次**

| 步骤 | 做什么 | 备注 |
|---|---|---|
| 1 | **`gates.ts` 填真逻辑** | 四道闸门按序过：`threshold` → `sustained` → `baseline` → `cooldown`，任一道不放行就压掉本次 |
| 2 | **建 `rule-threshold` 插件** | 消费 `metric` 批次 → 产生 `zhizhi.event`（内存 > 85% / CPU > 90% / C 盘 < 10%） |
| 3 | **建 `rule-sustained` 插件** | 记住「超标起始时刻」，满 2 分钟才放行 ⭐ **这是 M2 最硬的一条** |
| 4 | **接通 dispatcher + 一个最小通道** | 建 `channel-stdout`，把事件打成一行终端输出 —— 浮窗（M4）之前总得有个能看见的东西 |
| 5 | **冷却期必须记在内核** | 15 分钟窗口存在 `store` 里，**不许让插件自己记** —— 沉默机制是宪法，不是插件配置项 |
| ⚠️ | **`baseline`（基线偏移）建议先留空** | z-score 需要历史样本，而 `store` 现在还是空的 → **等 M7 记忆落地再填**，别提前付成本 |
| ✅ | **验收** | 编译一次（CPU 飙高）不报警；压着阈值 2 分钟才报；同事件 15 分钟内只报一次 |

> ⚠️ **开工前先读《只只-环境基线.md》。** 闸门本身不碰 Node 特性，但第 5 步要把状态落盘，涉及 `fs` —— 别凭印象。

## 附：项目一句话回顾（给自己看的）

> 起因是想养个桌宠，聊着聊着发现**真正想要的是「让电脑活起来」** —— 它能看着这台机器，知道谁在吃内存、什么时候该闭嘴，还能在有人偷偷加自启项时提醒我。
>
> 它不叫"监控工具"，它叫**只只**。**它的性格比它的功能重要。**
>
> 而这一切的起点，是一个每 5 秒打印一行 JSON 的终端。**M0 见。**
