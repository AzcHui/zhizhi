# 台词段落速查

台词本的结构是：

```json
{
  "id": "persona-mine",
  "name": "我的只只",
  "tone": "一句话描述语气",
  "lines": {
    "<event.type>": ["台词1", "台词2"],
    "*": ["没有专属台词时的兜底"]
  }
}
```

`lines` 的键是**事件类型**（`event.type`）。只只每产生一个事件，就按它的 `type` 到这里找池子。

---

## 一、每段什么时候说（**这是最容易写错的地方**）

| 键 | 触发时机 | 建议句数 | 必需占位符 |
|---|---|---|---|
| `chitchat` | **你在电脑前**，到点了说句闲话 | **30~40** | 无 |
| `chitchat_back` | 到点了但你**离开了**，攒着；**你回来**且攒话 ≥30 分钟 | 8~12 | 无 |
| `greeting` | 只只启动后第一帧上下文到达（「我醒了」） | 5~8 | 无 |
| `poked` | 你戳球**攒够次数（第 1 轮）** —— 它只吭声，**不躲** | 4~6 | 无 |
| `poked_again` | 你继续戳（**第 2 轮及以后**）—— 它烦了，**说话 + 躲开** | 4~6 | 无 |
| `cpu.high` | **CPU > 90%** 且持续 | 5~8 | `{value}` |
| `mem.high` | **内存 > 85%** 且持续 | 4~6 | `{value}` |
| `disk.tight` | **磁盘占用 > 90%**（>95% 时 severity=critical） | 3~5 | `{value}` 建议带 `{drive}` |
| `security.newAutostart` | 开机自启项里**多了一条** | 3~5 | `{name}` `{command}` |
| `security.autostartChanged` | 已有自启项的**命令被改了** | 2~4 | `{name}` |
| `security.autostartTrusted` | 新增项的**签名有效**（跟进信息，语气可放松） | 2~3 | `{name}` `{publisher}` |
| `security.autostartUnsigned` | 新增项**没有数字签名** | 2~3 | `{name}` |
| `security.autostartSigBroken` | 签名**不对劲 / 文件缺失** | 2~3 | `{name}` |
| `*` | 所有层都没有该类型的池子时的兜底（强烈建议有） | 2~3 | 无 |

> ⚠️ **`chitchat` vs `chitchat_back` 是最容易混的一对。**
> `chitchat` = 用户正坐在电脑前（`idleMs` 很小），所以**不能说「你半天没动了」「歇着呢」**。
> `chitchat_back` = 用户离开了 ≥30 分钟刚回来，**才能说「你可算回来了」，且不能说「忙着呢？」**。

> ⚠️ **`poked` vs `poked_again` 是递进关系，不是随机二选一。**
> 第一次被戳烦，它只是「哎哟」；接着戳，它才躲。所以 `poked` 的台词**不能有赶人的味道**（那会让「第 1 轮不躲」显得莫名其妙）。

## 二、占位符（写错就是静默错误）

只只会在说话前把这些占位符替换成真实数据。**写错或写漏不报错，用户会直接看到花括号字面量。**

| 占位符 | 出现在 | 含义 |
|---|---|---|
| `{value}` | `cpu.high` / `mem.high` / `disk.tight` | 当前数值（已取整，如 `93`） |
| `{drive}` | `disk.tight` | 盘符（如 `D:`） |
| `{count}` | 任意段 | **这是第几次**（同类型累计）。可用在不断重复的告警上：「都第 {count} 次了」 |
| `{name}` | `security.*` | 自启项名 / 进程名 |
| `{command}` | `security.newAutostart` | 该项启动的命令行 |
| `{publisher}` | `security.autostartTrusted` | 签名发布者（如 `Microsoft Windows`） |
| `{summary}` | 任意段 | 规则给的客观描述（一般不在台词里用） |

## 三、长度约束

| 项 | 限制 | 为什么 |
|---|---|---|
| 单句 | **建议 ≤ 40 字，硬上限 60 字** | 气泡宽 250 DIP、字号 12.5，一行约 18 字；**8 行上限 ≈ 140 字**，超了会内部滚动（台词不该让人滚） |
| 停留时长 | 由字数自动算（`2.0s + 0.09s/字`，最低 2.5s） | 太长的句子会挂 10 秒以上，很烦 |

注意：**英文和数字按「整词」吐出**（打字机不会出现 `Microsof` 这种半截），所以中英混排时实际观感会比纯中文慢一点。

## 四、段名总表（拼错 = 永远不生效）

上面第一节表里的 13 个键就是**全部已知段名**（12 个具体类型 + `*`）。

写一个不存在的键（比如 `cpu_high`、`chitchatBack`），**不会报错**，只是那一段永远用不上 —— 对应事件会由内置台词包接着说（混搭），再不行才是 `summary`、裸类型名（`cpu.high` 这种机器味）。所以：

- 只用上表的键
- `check-persona.mjs` 会检查未知键并给出 WARN

## 五、缺段会怎样 —— **是「混搭」，不是「退化」**

**关键事实：`data/user.json` 不是「替换内置」，而是「插在最前面的一层」。**

挑台词时按顺序问每一层，**谁有话说就用谁的**：

```
user.json（你写的，最先问）
  → persona-zhi（内置台词包）
    → learned.json（模型补的，最后）
```

所以**缺段不会变成机器味**，而是**由内置包接着说** —— 效果是**两套语气混搭**。这决定了两种模式：

| 你的目标 | 该覆盖多少段 |
|---|---|
| **只补几句 / 改改口气**（模式 B） | 覆盖想改的那几段就够，混搭可接受 |
| **换一整个人格**（模式 A） | **必须覆盖全部 12 个段**，否则会在同一段对话里听出两种语气 |

单层内部的挑句顺序（决定同一段里怎么选）：

```
① 池子里挑一句「没说过」的
② 全说过了 → 允许重复，从同一池子再挑
③ 该层压根没有这个池子 → 换下一层问
④ 所有层都没有 → 用事件自带的 summary
⑤ 连 summary 都没有 → 直接念事件类型名（最难看）
```
