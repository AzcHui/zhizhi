## 三、下一步动作（M3 拆解，可直接照着做）

**M3 目标**：🎨 **手感验证（P0-b）** —— 用最丑最快的办法，先把「**位置、尺寸、挡不挡**」这三个问题问明白。

> ⚠️ **M3 与 M4 之间有一道人工决策闸门：手感验证不过，就先不整容。**
> 花一周搭好 Tauri 才发现"这位置挡我"，那才是真浪费。

| 步骤 | 做什么 | 备注 |
|---|---|---|
| 1 | **PowerShell + WinForms 搓一个丑浮窗** | 半天、零安装、不需要 Rust。**先不接数据，摆到屏幕上纯看手感** |
| 2 | **命门扩展样式到位** | `WS_EX_NOACTIVATE`（点击不抢焦点）+ `WS_EX_TOPMOST`（置顶）+ `WS_EX_TOOLWINDOW`（不进 Alt+Tab）；PowerShell 里靠 `Add-Type` 调 user32 |
| 3 | **接通真数据（可选，但推荐）** | 读 `cli` 的 stdout（一行一个 JSON）显示 CPU / 内存 —— 这一步同时验证「stdout 是数据通道」这个约定到底好不好用 |
| 4 | **试三个位置** | 右下角 / 顶部居中 / 贴任务栏 —— 主观感受要**真的回答**，别客气 |
| ✅ | **验收** | 你能回答：「这个位置舒不舒服 / 会不会挡我 / 按钮够不够」 |

> 📌 顺手可验的硬指标：**点浮窗按钮后，去编辑器里按 Ctrl+V 能不能正常粘贴**（能粘贴 = 没抢焦点）。

### ✅ 已交付（留档）

**M2（2026-10-14）：四道闸门 + 分通道** —— 只只学会「该说才说」

| 交付 | 内容 |
|---|---|
| `core/gates.ts` | 四道真闸门：`threshold`（证据校验）→ `sustained`（持续判定）→ `baseline`（M7 占位）→ `cooldown`（冷却期），**按序短路**；时间状态全记在内核 `store`，**插件读不到也绕不过** |
| `core/voice.ts` 🆕 | 表达链：persona 优先 → 事件客观描述兜底 → 事件名保底（**空 loadout 也能说话**） |
| `core/registry.ts` | 支持多类型：`adoptProbe` / `adoptRule` / `adoptChannel` + 统一 `reject` |
| `plugins/rule-threshold` 🆕 | 指标 → 候选事件（同类命中取最严重的那条） |
| `plugins/channel-console` 🆕 | 承载 `info` / `warn` 的**弱**通道 |
| `plugins/channel-alert` 🆕 | 只承载 `critical` 的**强**通道（分通道原则的最小样本） |
| `cli/main.ts` | 事件流水线：`probe → bus(metric) → rule → 闸门 → bus(event.passed) → 说话 → dispatcher → channel` |
| 新参数 | `--sustain-ms` / `--cooldown-ms`（沉默机制的窗口可调；S2 会外置到 JSON） |

**M0 / M1（2026-10-14）** —— 骨架跑起来（**运行时依赖 0 个**）+ 插件机制可用（清单驱动、失败三分类可报告）。

**四条硬约束的取证结果（实测，非推断）**：

| 约束 | 结果 |
|---|---|
| ① `core` 零 UI 依赖 | ✅ 全量 grep 零外部 import；`dependencies` 为空对象 |
| ② 插件之间禁止互相 import | ✅ 六个插件只 import `node:*` 与 `@zhizhi/plugin-sdk`，**无一 import `@zhizhi/core`** |
| ③ 官方插件也用 `plugin-sdk` | ✅ 六个插件全是 `defineProbe/Rule/Channel(...)` 的产物，无内核特权 |
| ④ 插件加载失败不影响内核 | ✅ **三类失败实测全隔离**：插件缺失 / manifest 不合规 / 加载期抛错 —— 内核均照常跑完并输出指标 |
